# PHY301 学习树：从这里开始

这是一套放在本机的 PHY301 统计物理学习网页。它不是要求你把所有资料一次读完，而是按“前置知识 → 课程主线 → 作业与复习”的顺序，把陌生概念拆成可以一步步完成的学习节点。

建议第一次先用下面的“双击启动”。网页打开后，从“继续学习 / 推荐下一步”开始，不要因为看到整棵大树就试图一天学完。

## 一、最简单：双击启动

1. 在 Finder 打开文件夹：

   当前项目文件夹（通常名为 `PHY301`）

2. 双击：

   `打开PHY301学习树.command`

3. 启动器会自动：

   - 切换到这个项目所在目录；
   - 检查本机是否有 Node.js 和 npm；
   - 如果 `http://localhost:3000` 已经是 PHY301 学习树，就直接打开，不重复启动；
   - 如果端口 3000 被另一个本地网站占用，就明确报错，不会误开或启动第二个服务；
   - 如果尚未启动，就在后台运行网站；
   - 最多等待约 30 秒，网站准备好后用默认浏览器打开。

第一次双击时，如果 macOS 因安全设置阻止运行，可以在 Finder 中对该文件点右键，选择“打开”，再确认一次。不要把启动文件单独拖离项目文件夹；它需要和项目文件放在一起。

启动成功后，可以关闭这个终端窗口，后台网站仍会继续运行。再次双击启动器不会主动杀掉已有进程。

## 二、用终端启动

本项目要求 Node.js `22.13.0` 或更高版本。

打开“终端”，依次运行：

```bash
cd "<项目目录>"
node --version
npm --version
npm run dev
```

看到服务启动信息后，在浏览器访问：

```text
http://localhost:3000
```

也可以另开一个终端窗口运行：

```bash
open "http://localhost:3000"
```

手动以前台方式运行时，回到运行 `npm run dev` 的终端按 `Control + C` 可以停止该次服务。

如果提示依赖缺失，并且项目目录中确实没有 `node_modules`，先联网运行一次：

```bash
cd "<项目目录>"
npm install
```

再运行 `npm run dev`。不要在不明来源的网站粘贴终端要求的密码或令牌；本地学习网页本身不需要厦门大学资源港账号。

## 三、双击启动器的日志和 PID

启动器不会杀进程。它会把后台启动信息写到：

```text
<项目目录>/logs/phy301-site.log
```

新启动的后台 npm 进程号写到：

```text
<项目目录>/.phy301-site.pid
```

如果 30 秒后仍未打开，可以在终端查看最近日志：

```bash
cd "<项目目录>"
tail -n 80 logs/phy301-site.log
```

PID 文件只是一次启动记录，不代表网站一定仍在运行。判断网站是否可用，以浏览器能否打开 `http://localhost:3000` 为准。

## 四、网页里有什么

页面名称以后可能有少量调整，但学习结构应保持以下分工：

### 1. 今日入口 / 继续学习

告诉你当前最适合学习的一个节点。若前置知识未通过，会先引导到最小必要补课，而不是让你自己猜该回哪一章。

### 2. 学习树

展示从零基础桥梁到 Week 1–14 的依赖顺序：

- 数学、概率、热力学与 Hamilton 相空间前置；
- 微正则、正则、巨正则与相变；
- 量子语言、密度矩阵、BE/FD 统计；
- Bose 气体、Fermi 气体；
- 扩散、Langevin 与 Fokker–Planck；
- 作业、期中和总复习。

树是地图，不是要求一次全部展开。优先完成网页高亮的“下一步”。

### 3. 知识节点

每个节点会尽量按以下顺序教学：

1. 为什么要学；
2. 先修检查；
3. 直觉；
4. 精确定义；
5. 逐步推导；
6. 量纲、极限与符号检查；
7. 例题；
8. 自测与通过门槛。

长推导、补充数学和文献会放在可展开区域。主线看懂并通过自测后，可以先继续前进；遇到对应作业时再回来深挖。

### 4. 课程大纲与资料库

这里把老师 Week 1–14 的教学计划、课件、三套作业、答案和期中评分资料对应到学习节点。资料入口用于核对老师的语言与考核风格，不建议脱离学习节点按文件顺序硬翻。

### 5. 公式地图、术语与记号提醒

用于快速确认公式属于哪个系综、控制变量是什么，以及老师记号与常见教材记号的差异。公式地图适合复习，不替代推导和做题。

### 6. 参考阅读

参考教材按主题跳读。网页核心解释应足以走通主线；只有卡住、需要更完整推导或追溯来源时，才进入指定章节。不要把一本几百页教材当成进入下一节点的硬门槛。

## 五、怎样用才最高效

- 第一次先做入口检查。会的部分用新题证明后可以暂时跳过，不必重复读。
- 看例题前先在纸上写第一步；看懂答案不等于自己会做。
- 每次优先完成一个节点和它的自测，不追求“今天滚动了多少页”。
- gate 的证据没有逐项完成时，网页不会让该节点进入“暂时掌握”；先修节点未通过也不能越级完成后置节点。
- “暂时掌握”会生成立即、1、3、7、14、30 天复习；3 天新变式通过后才变成“已确认”。
- 延迟复习若没通过，会自动退回 1 天补救，并要求新的 3 天变式；旧的通过记录不能绕过新失败。
- 卡住时选择精确补洞：术语、数学、符号/单位、解题策略或前一知识点。
- 作业先看题目，再看逐级提示，最后才展开完整答案。
- 第二天先用几分钟闭卷回忆昨天内容，再学新内容。
- 老师原资料与标准公式不一致时，以网页中的纠错说明理解原因，并留意“考场如何声明记号”。

## 六、学习进度只保存在当前浏览器

当前学习进度保存在浏览器本机存储中，不是云同步，也不会自动跟随你的账号去另一台电脑。

请特别注意：

- 尽量一直使用同一台电脑、同一个浏览器、同一个浏览器用户资料；
- 无痕/隐私窗口通常不会长期保留进度；
- 清理“网站数据”、重置浏览器或更换浏览器后，进度可能丢失；
- `Safari` 中的进度不会自动出现在 `Chrome`，反之亦然；
- 浏览器进度与项目文件是两套东西：复制项目文件夹不等于复制浏览器中的学习记录。

网页“学习计划”页提供 JSON 导出和导入恢复；它可以保存 gate 证据、进度、诊断、笔记、复习队列和错因记录。导入时会重新核验依赖、gate 与复测证据，不会盲信文件里写的“已确认”。重要错题和阶段结论仍建议同时保留纸质或本地笔记。

## 七、本地课程资料与隐私

直接在本机用 `http://localhost:3000` 打开，不等于把网站发布到了互联网。项目中的老师课件、作业、答案、考试资料和本地参考书仍位于这台电脑上。

但“放在本地”不代表可以忽略隐私：

- 不要把本地地址、终端日志或课程资料随意发到公开群；
- 不要把账号、密码、Cookie、登录截图、学生证件或含学号的文件放进项目；
- 启动日志可能包含本机路径或报错信息，发给别人前先检查并隐去个人信息；
- 在公共或不可信网络环境下，不要主动做端口映射、内网穿透或把本地开发服务暴露给外网；
- 老师课件、作业答案、考试资料和教材可能受学校规则或版权限制，只用于个人学习并不自动取得公开传播许可。

这个启动器不会读取或保存厦门大学资源港账号，也不会自动登录任何学校系统。

## 八、以后上传 GitHub 前必须检查

`public/` 目录中的文件一旦随网站上传或部署，通常会变成可直接访问的公开资源。即使代码仓库设为 private，也不应把“private”当成版权和隐私免责。

上传前至少完成以下检查：

1. 只发布自己有权发布的代码、解释、图表和资料。
2. 不上传老师 PPT/PDF、作业答案、考试评分资料或整本教材，除非已经获得明确许可。
3. 对开放教材优先保留官方链接和规范引用，不要无必要重新托管整份文件。
4. 删除姓名、学号、邮箱、课程平台截图、聊天记录和其他个人信息。
5. 绝不提交密码、Cookie、令牌、`.env`、学校登录状态或浏览器数据。
6. 不提交运行产物和本地状态，例如日志、PID、缓存、数据库和 `.wrangler` 状态。
7. 逐项检查准备上传的文件，而不是只看文件夹名称。

建议发布前运行：

```bash
cd "<项目目录>"
git status --short
git diff --stat
```

再重点检查：

```text
public/materials/
public/readings/
logs/
.env*
.wrangler/
*.db
```

如果未来要公开发布，安全的默认方案是：公开自写学习网页与必要的开源代码；把受限课程文件留在本机；网页中用课程内部名称、页码索引或合法的官方链接代替原文件。

## 九、遇到问题时先检查

1. 浏览器地址是否正好是 `http://localhost:3000`。
2. `node --version` 是否达到 `22.13.0`。
3. `npm --version` 是否能正常输出。
4. 项目文件夹是否仍完整，启动器是否仍在项目根目录。
5. `logs/phy301-site.log` 最后 80 行写了什么。
6. 端口 3000 是否已经被另一个本地网站使用。

不要为了解决端口问题随意杀掉不认识的进程。先确认占用者，再决定是否关闭对应应用或改用其他端口。
